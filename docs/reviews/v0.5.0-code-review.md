## CRITICAL

### C1. Recovery-dialog closures act on the wrong session — `main.py:71`
`_on_compile`/`_on_keep`/`_on_delete` close over the loop variable `session`. With multiple recovered sessions, every dialog acts on the **last** one; clicking "Delete" on the dialog describing session 1 purges session N's recorded data.
**Fix:** bind per-iteration (`def _on_delete(session: ObserverSession = session) -> None:`) or build dialogs inside a helper taking `session` as a parameter.

### C2. Observer store `start()` ignores writer-thread init failure — `observer/store.py:193`
`start()` discards the `flush()` return. If the writer thread dies during init (schema mismatch, disk error, AV/file lock), the app continues with `_started=True` and a dead writer: `append()` silently enqueues into a queue nobody drains (**total silent loss of every recorded event** + unbounded memory growth), and every later `close_session` blocks 5 s then raises.
**Fix:** store the init exception in `_writer_loop`; in `start()`, raise `ObserverError` if flush returns `False` or the init error is set.

### C3. New recording can strand the in-flight pipeline and insert the next dictation twice — `core/orchestrator.py:1084`
With streaming on, the pipeline parks on `_stream_final_event.wait()` for seconds after stop. `prepare_for_recording` resets the streaming task but never cancels `_pipeline_task` (unlike `cancel()`), so a quick re-toggle strands pipeline P1 (dictation #1's text lost); P1 later wakes on the **same shared event** when dictation #2 finishes — both pipelines run, dictation #2's text is inserted twice, `ObserverUtteranceEvent` fires twice.
**Fix:** cancel any in-flight `_pipeline_task` in `prepare_for_recording`, or give each pipeline its own event/final-segment captured at stop time.

### C4. Excluded apps are recorded to the session archive — `observer/triggers.py:346` + `main.py` ambient wiring
Two related privacy-invariant breaks:
1. `_poll_once` records `focus_change` with `app_name` + full `window_title` **before** the exclusion check runs inside `gate.request()`. Focusing 1Password/InPrivate persists vault-item and private-tab titles into SQLite, and the rules compiler renders `window_title` as a markdown section header. `meta["previous_app"]` leaks the excluded app a second time on switch-away.
2. Ambient audio is **not** suspended during exclusion: the exclusion path writes a `pause_start` row but never pauses `AmbientListener`, so speech while an excluded app is focused is still transcribed and archived (`SessionManager.record` only gates on the hotkey pause).
**Fix:** run `ExclusionMatcher.is_excluded(app, title)` before recording; null the fields (or skip the row) when excluded; suspend ambient segmentation during exclusion; drop `previous_app` when the previous app was excluded.

### C5. Settings window can never save — `setup/settings_window.py:154`
Save/Apply/Discard states are computed from `controller.is_dirty()`, but pages only push widget edits into the controller during `_collect()` — which runs only in `_on_apply`/`_on_save`. At build time `is_dirty()` is False, all three buttons are disabled, and nothing ever re-enables them. The "Restart required" banner is dead UI for the same reason.
**Fix:** connect page change signals to a slot that collects and refreshes button/banner state.

### C6. Any settings save silently resets Observer storage paths and re-enables selection capture — `setup/pages/observer_page.py:281`
`save_to_controller` sends `storage`/`selection`/`compile` subsections **without** the unexposed fields (`storage.dir`, `compile.output_dir`, `selection.enabled`), and `ConfigController.update_section` merges only one level deep — so each subsection is replaced wholesale. Every save (wizard Finish and settings `_collect()` call *every* page's save) resets `observer.storage.dir` to the default, repins `output_dir`, and **flips `selection.enabled` back to True** — re-enabling highlighted-text capture the user deliberately disabled.
**Fix:** carry unexposed fields through from the current draft, or deep-merge dict values in `update_section` (fixes the whole class).

## Recommended landing order (v0.5.0 Track 1 prerequisites)

1. **C5 + C6 + H18-H25 (setup/ save pipeline)** — the settings surface is where every other fix gets configured; today it cannot save, and saves corrupt config.
