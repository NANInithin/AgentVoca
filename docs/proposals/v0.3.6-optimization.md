## 1. Executive summary

| Symptom the user sees | Verified root cause | Fix |
|---|---|---|
| Robotic / clipped audio under load | VAD ONNX inference runs **twice** per 64 ms block inside the sounddevice callback (`process_chunk` calls `is_speech` internally, then the callback calls it again — `capture.py:201-202`) | **R1**, **R2** |
| Audio glitch exactly at auto-stop | `stop_recording()` runs *inside the audio callback* on auto-stop and does `b"".join(self._audio_buffer)` — a full copy of the recording (~7.7 MB @ 2 min) on the real-time thread | **R3** |
| Stutter during >60 s dictations | O(N²) copying: `bytes(full_buffer)` per 500 ms chunk in `_run_streaming_asr` (~0.9 GB churn per 2-min dictation) | **R4** |
| High memory during long dictations | Three full copies of the recording live simultaneously (`AudioCapture._audio_buffer`, `AudioChunker._buffer`, streamer `full_buffer`); the chunker buffer never shrinks | **R5** |
| Ghost partials / wasted CPU after Cancel; Cancel after stop still inserts text | Cancel never reaches the orchestrator: the orphaned stream task keeps transcribing until the *next* recording, and an in-flight pipeline cannot be aborted | **R6** |
| — (hygiene) | Dead `_frame_queue` / `_frame_task` in `AudioCapture` | **R7** |
| Cloud cleanup pays a TLS handshake every dictation; `warm_up()` "primes the pool" but the pool is per-request, so it primes nothing | Throwaway `httpx.AsyncClient` per call in cleanup + vision providers; hot-reload also leaks clients | **R8** |
| Blocking file read on the event loop per cleanup call | `custom_prompt_path` is re-read from disk on **every** `rewrite()` | **R9** |
| Multi-screenshot sessions feel slow | Vision extractions run serially — 4 screenshots = 4 sequential VLM round-trips | **R10** |
| Interleaved keystrokes when undo fires during an insertion | pyautogui is not thread-safe; insert and undo run on different default-executor threads concurrently | **R11** |
| Scaling cliff with big vocabularies | O(terms) linear scan in `_replacement` per regex match | **R12** |
| Startup / settings-save hitch with many learned mappings | One full regex recompile **per learned mapping** in `_init_vocab_snippets` and `apply_config_update` | **R13** |
| Slow cold start, even for cloud-provider users | `main.py` imports `faster_whisper` → `ctranslate2` + numpy at module import, before `QApplication` exists — regardless of the configured provider | **R14** |
| Settings save can race the pipeline | `apply_config_update` mutates orchestrator state from the Qt thread while the loop thread reads it | **R8** (routing fix) |

No new features. No new runtime dependencies. No config-schema changes.
`shutdown()` on providers is a soft additive contract (checked via `getattr`).

## 2. Items

### Track 1 — Audio & Streaming (Agent 1)

- **R1 — Delete the duplicate VAD inference in the audio callback.**
  2-line diff, halves callback inference cost immediately. Ships first, independent of R2.

- **R2 — Move VAD inference off the audio callback (rewritten from old A1).**
  Thread-safe `queue.Queue` + a dedicated VAD worker **thread** (NOT the asyncio
  loop — inference must not block streaming ASR scheduling; and
  `asyncio.Queue.put_nowait` from the audio thread is not thread-safe, which
  killed the rev-1 sketch). Callback reads a cached `_last_vad_speech` bool.
  Correct math: callbacks arrive every ~64 ms (1024 frames @ 16 kHz), so a
  64-deep queue bounds staleness at ~4 s, and the drop-on-full policy plus a
  queue clear at `start_recording()` keeps auto-stop latency well under
  `silence_timeout_ms + a few blocks`.

- **R3 — Move `stop_recording()`'s buffer join + publish off the audio callback.**
  On auto-stop, only flip flags in the callback; schedule the join +
  `RecordingStoppedEvent` publish onto the asyncio loop thread.

- **R4 — O(N²) → O(N) streaming-ASR memory (old A2, corrected).**
  `memoryview` slice + single `.copy()` that *replaces* (not stacks on) the
  existing snapshot copy; build the window only when actually submitting a new
  partial. Explicit `BufferError` regression test (numpy export vs.
  `bytearray.extend` resize).

- **R5 — Compact `AudioChunker._buffer` after each delta emission.**
  Removes one of the three simultaneous full copies of the recording.

- **R6 — `Orchestrator.cancel()` wired to the cancel hotkey (old A5, reframed).**
  The rev-1 hang mechanism was wrong (`cancel_recording` never publishes
  `RecordingStoppedEvent`, and `prepare_for_recording()` already resets state
  before each recording). The *real* bugs: (a) the orphaned stream task keeps
  transcribing and publishing ghost partials until the next recording; (b)
  Cancel pressed while the pipeline is in flight does nothing — text still
  gets inserted. Fix: track the pipeline task, add `Orchestrator.cancel()`
  that cancels stream + pipeline tasks and resets state, wire it in
  `main.py`'s `on_hotkey` cancel branch, and guard `cancel_recording()`.

- **R7 — Remove dead `_frame_queue` / `_frame_task` from `AudioCapture`.**

### Track 2 — I/O, Text & Startup (Agent 2)

- **R8 — Persistent HTTP clients for cleanup + vision (old A4, extended).**
  Long-lived `httpx.AsyncClient` with `keepalive_expiry=30.0` set explicitly
  (httpx defaults to 5 s — shorter than the typical gap between dictations, so
  without this the reuse win evaporates). `warm_up()` must go through the
  shared client, otherwise it still primes nothing. `shutdown()` soft contract
  awaited in `Orchestrator.stop()` **and** in the hot-reload path, which
  currently leaks the old provider's client on every settings save. Hot-apply
  is additionally routed through the loop thread
  (`loop_thread.call_soon(orchestrator.apply_config_update, cfg)`), fixing the
  pre-existing Qt-thread/loop-thread mutation race.

- **R9 — Cache `custom_prompt_path` contents with an mtime check.**
  Removes synchronous file I/O from the async hot path.

- **R10 — Parallelize multi-screenshot vision extraction** with
  `asyncio.gather` (order-preserving, per-shot error isolation). In the
  4-screenshot scenario this saves seconds — more than R8's handshake savings.

- **R11 — One shared single-worker input executor (old A3, reframed).**
  Justification corrected: the default executor has `min(32, cpu+4)` workers,
  so a single `typewrite` starves nothing. The real bug is that pyautogui is
  not thread-safe and concurrent insert/undo interleave keystrokes. Therefore
  keyboard AND clipboard strategies must share **one module-level** pool
  (per-class pools would reintroduce the race), with an explicit
  `shutdown(wait=False)` at app exit (executor threads are non-daemon).

- **R12 — O(1) casing lookup in `VocabularyDictionary._replacement` (old B1).**
  First-wins dict semantics to preserve current behavior for terms differing
  only in case.

- **R13 — Batch the learned-mapping merge (replaces old B2).**
  Old B2's "mid-utterance recompile" cannot occur — promotion runs
  post-recording inside `_run_pipeline`. The real cost: `_init_vocab_snippets`
  and `apply_config_update` call `add_mapping()` in a loop and trigger one
  full pattern rebuild *per mapping*. Add `add_mappings()` bulk API → one
  rebuild per merge.

- **R14 — Lazy provider imports (replaces old C3).**
  Old C3 targeted the wrong cost (config load is milliseconds; the
  `ctranslate2`/numpy import chain is the real pre-paint stall) and its sketch
  was unimplementable (`asyncio.to_thread` with no running loop; config is
  needed synchronously by the first-run gate). Fix: registry stores dotted
  paths for builtins and resolves via `importlib` at instantiation, so cloud
  users never import ctranslate2 at all.

### Dropped from rev 1 (with reasons)

| Rev-1 item | Reason dropped |
|---|---|
| **A5 as written** | Described hang cannot occur; sketch was self-contradictory (queued `_STREAM_END`, set `_stream_final_event`, then called `_reset_streaming_state()` which cancels the consumer, clears the event, and drains the sentinel). Reframed as R6. |
| **B2 as written** | Premise false — no mid-utterance recompile exists; lazy rebuild just moves the compile to first `apply()`, which is where it already effectively is. Reframed as R13. |
| **C1 (`wait_idle` async event)** | Low ROI; the current `asyncio.to_thread` wait is bounded at 2 s, and a correct replacement needs cross-thread `Event` handling plus multi-capture-in-flight semantics. Not worth it. |
| **C2 (compute-type probe cache)** | Premise false — `_probe_compute_type` runs only inside the model-load path behind `if self._model is not None: return`, i.e. once per load, not per call. |
| **C3 as written** | See R14. |

## 3. Test & verification plan (restructured)

**`MOCK_BUDGETS_MS` is NOT extended.** Rev 1 proposed mock-benchmark rows
(`audio_callback_p99_ms`, `asr_streaming_churn_mb`, `cleanup_tcp_connects`)
that mock mode cannot measure — `benchmark.py --mode mock` drives the
orchestrator with mock providers and never touches `AudioCapture`,
`FasterWhisperProvider`, or real HTTP. Those metrics live in the integration
tests below instead. Rev 1's tightening of the mock `asr` budget (75→35 ms)
is also dropped: R4 changes `faster_whisper.py`, which mock mode never runs.

New tests (each lands with its fix; details in the agent plans):

Track 1:
- `tests/unit/test_capture_vad_worker.py` — R1/R2: single inference per block; callback p99 < 5 ms over a synthetic 30 s stream; auto-stop still fires within `silence_timeout_ms + 3 blocks`.
- `tests/unit/test_capture_stop_offthread.py` — R3: callback never joins the buffer; `RecordingStoppedEvent` published from the loop thread with identical payload.
- `tests/unit/test_streaming_no_quadratic_copy.py` — R4: bounded allocation churn (tracemalloc) + `BufferError` regression case.
- `tests/unit/test_chunker.py` (extend) — R5: buffer length stays bounded across emissions; deltas byte-identical to rev-1 behavior.
- `tests/integration/test_cancel_semantics.py` — R6: no `PartialTranscriptEvent` after cancel; cancel-after-stop aborts insertion; next dictation completes normally.

Track 2:
- `tests/unit/test_cleanup_persistent_client.py` / `test_vision_persistent_client.py` — R8: same client object across calls (mock transport counts connections); `shutdown()` closes it; hot-reload closes the *old* provider's client. (True socket-reuse assertions need a real local server — out of scope for unit CI; client-identity + transport instrumentation is the CI-able proxy.)
- `tests/unit/test_cleanup_prompt_cache.py` — R9: one read per mtime; re-read after touch.
- `tests/integration/test_vision_parallel.py` — R10: wall time ≈ max(per-shot), not sum; one failure doesn't drop the rest; order preserved.
- `tests/unit/test_insertion_serialized.py` — R11: concurrent insert+undo never overlap in time; shared pool across both strategies.
- `tests/unit/test_vocab_lookup.py` — R12: 5,000-term dictionary, `apply()` p95 budget **measured first, then set** (the 5,000-branch regex alternation may dominate; do not commit a 2 ms number blind); first-wins casing behavior.
- `tests/unit/test_vocab_bulk_mappings.py` — R13: exactly one `_build_pattern` call per bulk merge (counter monkeypatch).
- `tests/unit/test_lazy_provider_imports.py` — R14: subprocess asserts `ctranslate2 not in sys.modules` after registry construction + cloud-provider instantiation.

Per-merge gate (both tracks):
```
uv run pytest -q
uv run ruff check src/ tests/
uv run python scripts/benchmark.py --mode mock
```
Manual smoke per track before release: 90 s dictation on a 6 GB-VRAM machine;

## 5. Risks & rollback

Every fix is independently revertible. Corrected per-fix risks:

| ID | Risk | Mitigation |
|---|---|---|
| R2 | Auto-stop staleness if the VAD worker lags | Queue cleared at `start_recording`; drop-on-full; staleness test asserts stop within `silence_timeout_ms + 3 blocks` |
| R3 | Ordering vs. chunker flush | Flush is already scheduled via `run_coroutine_threadsafe`; publish is scheduled after it on the same loop — order preserved |
| R4 | `BufferError` if a numpy view outlives an iteration | Copy-then-release pattern with explicit `del`; dedicated regression test |
| R5 | Cross-thread `del` on the bytearray vs. `extend` | Both are single GIL-held C ops; delete only up to a pre-read snapshot length so appended bytes survive; unit-tested |
| R6 | Cancelling a pipeline mid-insertion leaves half-typed text | Accepted (same as today's behavior when nothing aborts); cancellation checkpoint is placed *before* insertion starts |
| R8 | Stale pooled connection after long idle | `keepalive_expiry=30.0`; httpx retries transport errors on a fresh connection for idempotent requests — verify with the persistent-client test |
| R11 | Non-daemon executor thread delays app exit | Explicit `shutdown(wait=False)` in `main.py` `finally` |
| R12/R13 | Behavior drift for case-variant terms | First-wins dict; regression test |
| R14 | A provider module with import-time side effects breaks when deferred | `_register_cuda_dlls()` runs at `faster_whisper.py` import — it still runs at first instantiation, before any model load; covered by the lazy-import test |

Hot-reload interaction: R8's routing change makes `apply_config_update` run on
the loop thread; the existing settings-window tests must still pass (they call
it directly, which remains supported — the method itself stays synchronous).
