## Step 1 — R12: O(1) casing lookup in `VocabularyDictionary`

**File:** `src/agentvoca/vocab/dictionary.py`.

**Problem (verified):** `_replacement` linear-scans `self._terms` on every
regex match — O(matches × terms).

**Change:** maintain a lowercase→original dict rebuilt whenever the pattern is
rebuilt. Centralize both in one `_rebuild()`:

```python
def _rebuild(self) -> None:
    """Recompile the match pattern and the casing lookup together."""
    self._pattern = _build_pattern(self._terms)
    casing: dict[str, str] = {}
    for term in self._terms:
        casing.setdefault(term.lower(), term)   # first-wins: matches old scan order
    self._casing = casing
```

- Replace the two existing `self._pattern = _build_pattern(self._terms)` call
  sites (`__init__`, `add_terms`) with `self._rebuild()`.
- `setdefault` is required: the old scan returned the **first** case-variant
  in the list; a plain dict-comprehension would keep the last and silently
  change behavior for vocabularies containing e.g. both `polars` and `Polars`.
- New `_replacement`:

```python
def _replacement(self, match: re.Match) -> str:
    matched = match.group(1)
    lower = matched.lower()
    mapped = self._mappings.get(lower)
    if mapped is not None:
        return mapped
    return self._casing.get(lower, matched)
```

**Tests:** new `tests/unit/test_vocab_lookup.py`:
1. **Behavior:** identical output to the old implementation for: plain terms,
   ` -> ` mappings, case-variant duplicate terms (first-wins), terms with
   non-word chars (`C++`, `C#`).
2. **Scale:** build a 5,000-term dictionary, apply to a ~1,000-word transcript
   containing ~50 matches. **Measure before asserting**: print p95 over 20
   runs, then set the CI ceiling at ~3× the measured p95. Do NOT hard-code
   the rev-1 "2 ms" number — with 5,000 regex alternations the pattern itself
   may dominate and the honest budget might be higher. Record the measured
   number in the test's docstring.

## Step 2 — R13: batch the learned-mapping merge

**Files:** `src/agentvoca/vocab/dictionary.py`,
`src/agentvoca/core/orchestrator.py` (`_init_vocab_snippets`,
`apply_config_update` only).

**Problem (verified):** `add_mapping()` → `add_terms([wrong])` → full pattern
rebuild, called **in a loop** at `orchestrator.py:305-307` (startup merge) and
`orchestrator.py:1186-1187` (every settings save). N mappings = N recompiles
of the entire pattern.

**Change 2a — bulk API in `dictionary.py`:**

```python
def add_mappings(self, mappings: Iterable[tuple[str, str]]) -> None:
    """Add many wrong→right mappings with a single pattern rebuild."""
    changed = False
    for wrong, right in mappings:
        self._mappings[wrong.lower()] = right
        if wrong not in self._terms:
            self._terms.append(wrong)
            changed = True
    if changed:
        self._rebuild()
```

Keep `add_mapping()` delegating to it (`self.add_mappings([(wrong, right)])`)
so single-promotion behavior (adaptive path) is unchanged.

**Change 2b — call sites in the orchestrator:** replace both `for wrong,
right in ...: self._vocab.add_mapping(wrong, right)` loops with
`self._vocab.add_mappings(self._adaptive_store.get_mappings())`.

Note: `if wrong not in self._terms` inside the loop is still O(terms) per
mapping; if the Step-1 measurements show it matters, use a transient
`set(t for t in self._terms)` inside `add_mappings`. Don't restructure
`_terms` itself (it's ordered and exposed via the `terms` property).

**Tests:** new `tests/unit/test_vocab_bulk_mappings.py`:
- Monkeypatch `agentvoca.vocab.dictionary._build_pattern` with a counting
  wrapper; call `add_mappings` with 200 pairs; assert exactly **1** call
  (vs. 200 before). Assert all 200 mappings apply correctly afterward.
- Assert `add_mapping` (singular) still rebuilds and still works.

## Step 3 — R9: cache the custom cleanup prompt

**File:** `src/agentvoca/cleanup/openai_compatible.py`, `rewrite()` (~lines
99–104).

**Problem (verified):** `custom_prompt_path` is `open()`-ed and read on
**every** `rewrite()` call — synchronous file I/O directly on the event loop,
in the hot path.

**Change:** cache `(mtime, content)` on the instance; a single `os.stat` per
call replaces the read (stat is microseconds; acceptable on the loop):

```python
# __init__
self._prompt_cache: tuple[float, str] | None = None

def _load_custom_prompt(self) -> str:
    """Read custom_prompt_path, cached by mtime so edits are picked up."""
    path = self._config.custom_prompt_path
    try:
        mtime = os.stat(path).st_mtime
    except OSError as e:
        raise CleanupError(f"Failed to load custom prompt file: {e}")
    if self._prompt_cache is not None and self._prompt_cache[0] == mtime:
        return self._prompt_cache[1]
    try:
        with open(path, "r", encoding="utf-8") as f:
            content = f.read()
    except Exception as e:
        raise CleanupError(f"Failed to load custom prompt file: {e}")
    self._prompt_cache = (mtime, content)
    return content
```

In `rewrite()`, replace the inline open with
`custom_prompt = self._load_custom_prompt()` (same guard: only when
`not custom_prompt and self._config.custom_prompt_path`). Error semantics —
raising `CleanupError` on unreadable file — must stay identical (existing
tests in `test_cleanup_openai_compatible.py` / `test_openai_cleanup.py` may
assert it).

**Tests:** new `tests/unit/test_cleanup_prompt_cache.py` (use `tmp_path`):
- Two `rewrite()` calls (mock the HTTP layer) → file read once (count via
  monkeypatched `open` or a stub path object).
- Touch the file with new content + newer mtime → next call picks it up.
- Missing file → `CleanupError`, same message prefix as before.

## Step 4 — R11: one shared input executor for all pyautogui/pyperclip calls

**Files:** new `src/agentvoca/insertion/_executor.py`,
`src/agentvoca/insertion/keyboard.py`, `clipboard.py`,
`src/agentvoca/main.py` (shutdown `finally` only).

**Problem (verified):** every pyautogui call goes through the *default*
executor (`run_in_executor(None, ...)`). pyautogui is not thread-safe: an undo
hotkey (`orchestrator.undo_last_insertion`) can run `press("backspace", ...)`
concurrently with an in-flight `typewrite`, interleaving keystrokes. (The
rev-1 "starvation" story was wrong — the default pool has `min(32, cpu+4)`
workers — serialization is the actual requirement, which is also why **both**
strategies must share **one** pool, not per-class pools.)

**Change 4a — the shared pool:**

```python
# src/agentvoca/insertion/_executor.py
"""Single-worker executor serializing all OS input injection.

pyautogui (and the clipboard+paste dance) are not thread-safe; running an
undo concurrently with an in-flight typewrite interleaves keystrokes in the
target app. Every pyautogui/pyperclip call in the insertion package must go
through INPUT_EXECUTOR.
"""
from concurrent.futures import ThreadPoolExecutor

INPUT_EXECUTOR = ThreadPoolExecutor(max_workers=1, thread_name_prefix="agentvoca-input")

def shutdown_input_executor() -> None:
    """Best-effort shutdown; wait=False so a stuck typewrite can't hang exit."""
    INPUT_EXECUTOR.shutdown(wait=False, cancel_futures=True)
```

**Change 4b — route every call through it.** In `keyboard.py` and
`clipboard.py`, replace each
`asyncio.get_event_loop().run_in_executor(None, <fn>)` and
`loop.run_in_executor(None, <fn>)` with:

```python
await asyncio.get_running_loop().run_in_executor(INPUT_EXECUTOR, <fn>)
```

Call sites to convert (grep `run_in_executor` in the package; the snapshot
shows): `keyboard.insert` (typewrite), `keyboard.undo_last` (focus_window,
backspace press, ctrl+z), `clipboard.insert` (pyperclip.copy, paste hotkey),
`clipboard.undo_last` (ctrl+z). The `get_event_loop()` → `get_running_loop()`
swap also clears a deprecation.

**Change 4c — shutdown.** In `main.py`'s `finally` block (after
`overlay.stop()`, before `loop_thread.stop()`):

```python
from agentvoca.insertion._executor import shutdown_input_executor
shutdown_input_executor()
```

(Import at top of `main.py` with the other insertion import.) Rationale:
executor threads are non-daemon; without this a wedged pyautogui call delays
process exit.

**Tests:** new `tests/unit/test_insertion_serialized.py`:
- Monkeypatch `pyautogui.typewrite` and `pyautogui.press` with stubs that
  record `(start_time, end_time)` and sleep 100 ms. Fire
  `KeyboardInsertionStrategy.insert("abc")` and `undo_last()` concurrently via
  `asyncio.gather`; assert their recorded intervals do **not** overlap.
- Assert `keyboard` and `clipboard` strategies resolve to the *same* executor
  object (identity check on the module attribute).
- Existing `tests/unit/test_insertion.py` and
  `tests/integration/test_insertion.py` must pass unmodified.

## Step 5 — R8: persistent HTTP clients (cleanup + vision) with real lifecycle

**Files:** `src/agentvoca/cleanup/openai_compatible.py`,
`src/agentvoca/vision/openai_compatible.py`, `core/orchestrator.py`
(`stop()`, `apply_config_update`), `main.py` (`_reload_hot_components`).

**Problem (verified):** both providers open a throwaway
`httpx.AsyncClient` per request (`cleanup:128`, `vision:130`), paying TCP+TLS
per dictation. `warm_up()` (`cleanup:55`) uses *another* throwaway client, so
its documented purpose — "prime the HTTP connection pool" — has never worked.
Hot-reload (`orchestrator.apply_config_update:1215`) replaces the provider and
would leak the old client.

**Change 5a — the client.** In each provider's `__init__`:

```python
self._client = httpx.AsyncClient(
    timeout=30.0,   # keep 60.0 in the vision provider — VLM calls are slower
    limits=httpx.Limits(
        max_connections=4,
        max_keepalive_connections=4,
        keepalive_expiry=30.0,   # httpx default is 5 s — shorter than the
                                 # gap between dictations, which would erase
                                 # the reuse win. 30 s covers a dictation cadence.
    ),
)
```

(`httpx.AsyncClient(...)` does not require a running loop at construction;
providers are built in `Orchestrator.start()` on the loop thread anyway.)

- `rewrite()` / `extract()`: replace the `async with httpx.AsyncClient(...)`
  block with direct `await self._client.post(...)`. Exception mapping stays
  byte-identical.
- `warm_up()`: use `self._client.get(url, ...)` — **this is the point**; with
  the shared client the warm-up finally pre-opens the connection the first
  real request will reuse. Keep the shorter effective timeout by passing
  `timeout=5.0` to the individual `.get()` call.
- New method on both providers:

```python
async def shutdown(self) -> None:
    """Close the pooled HTTP client. Safe to call more than once."""
    await self._client.aclose()
```

**Change 5b — shutdown on stop.** In `Orchestrator.stop()`, after the
task-cancellation section:

```python
for provider in (self._cleanup_provider, self._vision_provider, self._asr_provider):
    shutdown = getattr(provider, "shutdown", None)
    if shutdown is not None:
        try:
            await shutdown()
        except Exception:
            logger.debug("Provider shutdown failed", exc_info=True)
```

Soft contract: providers without `shutdown` are untouched; do not add it to
the base classes.

**Change 5c — fix the hot-reload leak + thread race.** Two coordinated edits:

1. `main.py`, `_reload_hot_components`: route the hot-apply through the loop
   thread instead of calling it on the Qt thread:

```python
if orchestrator is not None:
    loop_thread.call_soon(orchestrator.apply_config_update, new_config)
```

   (The method stays synchronous; `call_soon` callbacks run inside the
   running loop, so `asyncio.get_running_loop()` works within it. This also
   fixes the pre-existing race where the Qt thread swapped `_vocab` /
   `_cleanup_provider` under the pipeline's feet.)

2. `orchestrator.apply_config_update`, cleanup-provider branch: close the old
   provider's client before dropping the reference:

```python
old_provider = self._cleanup_provider
self._cleanup_provider = self._registry.get_cleanup(new_config.cleanup)
old_shutdown = getattr(old_provider, "shutdown", None)
if old_shutdown is not None:
    asyncio.get_running_loop().create_task(old_shutdown())
```

Guard the `get_running_loop()` for the direct-call path used by tests
(`tests/integration/test_settings_window.py` calls `apply_config_update`
synchronously): wrap in `try: loop = asyncio.get_running_loop() ... except
RuntimeError: asyncio.run(old_shutdown())` or simply skip the close when no
loop is running and log at debug. Check what that test actually does before
choosing; the method must keep working when called directly.

**Tests:** new `tests/unit/test_cleanup_persistent_client.py` and
`tests/unit/test_vision_persistent_client.py`:
- Build the provider with `httpx.MockTransport` (inject via monkeypatching
  `httpx.AsyncClient` construction or a small `_make_client` seam — add the

- `await provider.shutdown()` → client `.is_closed` is True; second

- Hot-reload: build orchestrator with a fake registry; run

- Existing `test_cleanup_openai_compatible.py`, `test_openai_cleanup.py`,

## Step 6 — R10: parallelize multi-screenshot vision extraction

**File:** `src/agentvoca/core/orchestrator.py`, `_apply_vision` only
(~lines 1083–1093).

**Problem (verified):** the per-shot `await self._vision_provider.extract(...)`
loop is serial; 4 screenshots = 4 sequential VLM round-trips (seconds each).

**Change:** run them concurrently, preserving order and per-shot error
isolation:

```python
async def _extract_one(shot: bytes) -> Optional[str]:
    try:
        extracted = await self._vision_provider.extract(shot, instruction=text, context=context)
    except VisionError as exc:
        logger.warning("Vision extraction failed for a screenshot: %s", exc)
        return None
    return extracted.strip() if extracted and extracted.strip() else None

results = await asyncio.gather(*(_extract_one(s) for s in shots))
extractions = [r for r in results if r]
```

`asyncio.gather` preserves input order, so anchor splicing sees the same
ordering as before. The persistent client from Step 5 has
`max_connections=4`, which naturally caps concurrency at 4; if the user
somehow queued more shots, httpx queues the excess — no extra semaphore
needed, but say so in a comment.

**Tests:** new `tests/integration/test_vision_parallel.py` (model on
`test_vision_pipeline.py`):
- Fake vision provider with a 300 ms `asyncio.sleep` per `extract`; 3 shots;
  assert `_apply_vision` wall time < 600 ms (parallel) not ≥ 900 ms (serial).
- One shot raises `VisionError` → the other two still splice, in original
  order.
- Zero extractions → `(text, False)` unchanged.

## Step 7 — R14: lazy provider imports (cold-start)

**Files:** `src/agentvoca/core/registry.py`, `src/agentvoca/asr/__init__.py`,
`cleanup/__init__.py`, `vision/__init__.py`, `src/agentvoca/main.py`.

**Problem (verified):** `main.py` does `from agentvoca.asr import
BUILTIN_ASR_PROVIDERS`, and `asr/__init__.py` eagerly imports
`faster_whisper.py`, which imports `ctranslate2`, numpy, and walks
site-packages for CUDA DLLs — all before `QApplication` exists, and even when
the configured provider is a cloud one that never needs ctranslate2.

**Change 7a — dotted-path builtins in the registry.** In
`registry.py`, allow registered values to be either a class **or** a
`"module:ClassName"` string, resolved on first `get_*`:

```python
def _resolve(self, entry: "Type | str") -> type:
    """Resolve a lazily-registered 'module:Class' path to the class."""
    if isinstance(entry, str):
        module_name, _, class_name = entry.partition(":")
        module = importlib.import_module(module_name)
        return getattr(module, class_name)
    return entry
```

- `_register_builtins()` stops importing the provider packages; it registers
  strings directly:

```python
self.register_asr("faster_whisper", "agentvoca.asr.faster_whisper:FasterWhisperProvider")
self.register_asr("openai_compatible", "agentvoca.asr.openai_compatible:OpenAICompatibleASRProvider")
self.register_cleanup("none", "agentvoca.cleanup.none:NoneCleanupProvider")
self.register_cleanup("openai_compatible", "agentvoca.cleanup.openai_compatible:OpenAICompatibleCleanupProvider")
self.register_cleanup("rules", "agentvoca.cleanup.rules:RulesCleanupProvider")
self.register_vision("openai_compatible", "agentvoca.vision.openai_compatible:OpenAICompatibleVisionProvider")
# insertion strategies are light (pyautogui only) but register lazily too for symmetry:
self.register_insertion("keyboard", "agentvoca.insertion.keyboard:KeyboardInsertionStrategy")
self.register_insertion("clipboard", "agentvoca.insertion.clipboard:ClipboardInsertionStrategy")
```

- In each `get_*`, replace `cls = self._asr.get(name)` usage with
  `entry = self._asr.get(name)` → `cls = self._resolve(entry)`, and cache the
  resolved class back into the dict so the import happens once. Widen the
  type annotations (`dict[str, Type[ASRProvider] | str]`).
- `register_*` keeps accepting classes (tests and plugins rely on it); only
  the *builtin* registrations become strings.
- Docstring note in `_register_builtins`: `faster_whisper.py` runs
  `_register_cuda_dlls()` at import time — with lazy loading this now happens
  at first instantiation, which is still before any model load, so behavior
  is preserved.

**Change 7b — provider `__init__.py` files.** They currently eagerly import
every provider for `BUILTIN_*` dicts. Keep the dicts for backward
compatibility but make them lazy via module `__getattr__` (PEP 562):

```python
# agentvoca/asr/__init__.py
"""ASR provider adapters. Provider classes are imported lazily (PEP 562) so
that importing this package does not pull in ctranslate2/numpy."""
from agentvoca.asr.base import ASRProvider

_LAZY = {
    "FasterWhisperProvider": "agentvoca.asr.faster_whisper",
    "OpenAICompatibleASRProvider": "agentvoca.asr.openai_compatible",
}

def __getattr__(name: str):
    if name == "BUILTIN_ASR_PROVIDERS":
        import importlib
        return {
            "faster_whisper": getattr(importlib.import_module(_LAZY["FasterWhisperProvider"]), "FasterWhisperProvider"),
            "openai_compatible": getattr(importlib.import_module(_LAZY["OpenAICompatibleASRProvider"]), "OpenAICompatibleASRProvider"),
        }
    if name in _LAZY:
        import importlib
        return getattr(importlib.import_module(_LAZY[name]), name)
    raise AttributeError(name)
```

Apply the same pattern to `cleanup/__init__.py` and `vision/__init__.py`.
`insertion/__init__.py` may stay eager (no heavy imports) — leave it.

**Change 7c — `main.py`.** Delete the now-redundant eager work:
- Remove `from agentvoca.asr import BUILTIN_ASR_PROVIDERS` (and the cleanup /
  insertion / vision equivalents) from the imports.
- Simplify `_build_registry()` to `registry = ProviderRegistry()` (builtins
  self-register lazily) plus the existing log line using `registry.list_*()`.
- Check nothing else in `main.py`'s import block transitively imports
  `agentvoca.asr` eagerly (`setup/` wizard pages may — follow the chain with
  the verification test below and fix only what the test flags, using local
  imports as `setup/pages/asr_page.py` etc. already do elsewhere).
